- Publication: no PR before Stage 0 `GO_ENGINE`, Stage 1-3 evidence, real screenshots where a web surface exists, 10 functional commits, repository age >=24h, and Claude `GO`.

- Cordis source exploration proves `ctx.timeout()` and `ctx.interval()` are implemented through `ctx.effect()` and return disposers; timer cleanup is therefore observable through Fiber disposables when the timer plugin is present. `Loader` listens to `internal/plugin`, associates fibers with loader entries, and its entry `init()` calls `ctx.registry.plugin()`; `Entry.update()` calls `fiber.dispose()` when disabled and emits `loader/partial-dispose` on changes.
- Harness root rules confirm ESM, `ctx.effect()`/`ctx.on()` registration discipline, fail-loud misconfiguration, explicit profile isolation, and a preference for capability seams over loop changes. These rules are treated as constraints for any optional DSH surface.
- `EventsService` is a public service with `ctx.on()`/`once()` disposers, but its `_hooks` map is an internal/private observation surface. Registration itself uses `ctx.fiber.effect()` and therefore can be audited as a managed disposable only through the owning fiber.
- `Fiber._disposables` is explicitly exposed with a leading underscore and `getEffects()` maps internal effect metadata; both must be adapter-only and version-gated. `Fiber.dispose` is async (`() => Promise<void>`), and `FiberState` includes `PENDING`, `LOADING`, `ACTIVE`, `FAILED`, `DISPOSED`, and `UNLOADING`, enabling lifecycle state checks when the adapter proves the structure.
- `RegistryService.plugin()` is the managed mount point: it validates the plugin, asserts an active context, creates/reuses runtime metadata, constructs a `Fiber`, and returns a thenable fiber. `RegistryService._internal` is private, while `size/keys/values/entries/has/get/delete` are public methods; registry counts alone do not prove all resource cleanup.
- `ModuleLoader.fromInternal()` branches on Node major version (v1 for Node 22, v2 for Node 24) and reads `internal/modules/esm/loader`; this is explicitly unstable and must never be treated as a universal public observation surface. Unknown Node/version or missing internal loader must produce `UNVERIFIABLE_VERSION`/surface failure.
- Source package identity is Cordis `4.0.0-rc.8` (`packages/core`) with timer plugin `1.1.2`; the Harness source declares Node `^22.19.0 || >=24.0.0` and uses pnpm `11.7.0`. The adapter support matrix will initially pin the tested Cordis core version and require the observed Fiber/Registry fields before mounting.
- Stage 0 decision: `GO_ENGINE` is technically justified for an independent engine with a versioned Cordis adapter. The lifecycle path is mount via public `ctx.registry.plugin()`, await the returned thenable/fiber, dispose via async `fiber.dispose()`, await settle, and compare adapter snapshots. This is not a `GO_UI` decision: live DSH unload and browser evidence remain optional and later.

- Dispose failures are swallowed by Cordis `_unload()` after logging. The engine must therefore use a bounded logger cursor/error projection during the dispose phase; relying only on a rejected `fiber.dispose()` promise would miss real disposer failures.

Adapter reads are side-effect-free, so observer noise is excluded by construction and verified with repeated identical snapshots.

## Findings

1. **Fail-closed outcome mapping is real and exit codes are distinct.** `src/contracts.ts:19-29` defines nine outcomes with `PASS: 0` only, enforced by `tests/contracts.test.ts:45` (`exitCode === 0` iff `outcome === 'PASS'`). `scripts/real-gate.ts:117-143` re-checks the *child process* exit code against `EXIT_CODES[expected]` plus receipt `outcome`/`exitCode`/`schemaVersion`/`fixture`/`packageName`/`packageVersion`/`sourceHash`, so CLI→exit wiring is proven behaviorally, not only by unit assertion.

2. **Private-surface handling is centralized in one adapter and drifts closed.** All private projections (`registry.entries/plugin/size`, `fiber.uid/state/dispose/getEffects`, `events._hooks`, `reflect.store`, `logger.buffer`) are touched only inside `src/cordis-adapter.ts`; `probe()` (`:178-210`) returns `UNVERIFIABLE_SURFACE`/`UNVERIFIABLE_VERSION` before any mount, and deeper structural drift throws `AdapterSurfaceError` at `:106,124,142,219,231,246,261`. `stateLabel()` rejects any fiber state outside the pinned 4.0.1 enum instead of coercing. Version pinning is exact string equality on name and version (`:179-187`), and `tests/real-cordis.test.ts:71-78` proves the drift path on the real runtime, not a fake.

3. **No path can reach `PASS` through an error.** In `src/engine.ts`, `PASS` is reachable only at `:295-297` after: successful probe, successful baseline snapshot, mount awaited within timeout, exercise completed, dispose awaited within timeout, no `unmount`-phase logged error (`:263`), and a stable settle snapshot. Every early return uses a non-`PASS` outcome, and baseline-snapshot drift maps to `UNVERIFIABLE_SURFACE` (`:176-187`). I found no branch that swallows an error and continues to comparison.

4. **The swallowed-disposer-error capture works on the real runtime, not just in theory.** Cordis absorbs disposer throws, so the engine snapshots the logger cursor before dispose (`:231`) and reclassifies via `errorsSince` (`:235,263`). `artifacts/stage-2/throwing-disposer/receipt.json:169-176` shows exactly one `{phase: "unmount", name: "Error"}` entry and `FAIL_DISPOSE` / exit 21 with `delta` empty — i.e. this case would otherwise have been a false `PASS`, and the raw evidence confirms it is not. Cursor filtering is `sn > cursor` on a monotonic sequence, so buffer trimming of *older* entries cannot mask a new one.

5. **Leak detection is genuine and directionally safe.** `artifacts/stage-2/leaky/receipt.json:458-511` shows 8 added records spanning fiber, effects, listener, registry runtime, and service, with the target fiber correctly gone — the fixture leaks through `context.root.plugin(...)`, i.e. a sibling the target's dispose cannot reach, which is a real leak, not a self-inflicted artifact. `compareSnapshots` keys on category+identity+label+owner+state (`src/compare.ts:7-15`); registry identities are positional (`runtime:${index}:${name}`, `cordis-adapter.ts:222`), which makes reported identities shift when siblings unmount (visible as `runtime:1:` → `runtime:0:` between mount and unmount in that receipt). This can only *add* spurious delta entries, never empty a non-empty delta, so it cannot downgrade a leak to `PASS`; it is a labeling weakness, not a soundness hole.

6. **Settle stability is asserted, and its failure mode is conservative.** `settle()` (`engine.ts:133-147`) requires two consecutive equal snapshots inside the window, else `FAIL_TIMEOUT`; proven by `tests/engine.test.ts:215-230` with an oscillating snapshot. A slow-but-eventually-clean disposer is reported `FAIL_LEAK` (false positive), never `PASS`.

7. **Single-run lock cannot be bypassed and does not mount.** `acquire()` uses `open(lockPath, 'wx', 0o600)` and converts only `EEXIST` into `AuditLockedError` (`src/lock.ts:21-31`); other errno values propagate rather than degrading. `tests/engine.test.ts:232-254` asserts `FAIL_LOCKED` *and* `mounted === false`.

Error surfaces are reduced to `name` plus a whitelisted `/^[A-Z][A-Z0-9_]{0,63}$/` code — messages are never serialized (`cordis-adapter.ts:166-175`, `engine.ts:91-104`), asserted for both fake (`engine.test.ts:162`) and real (`real-cordis.test.ts:66`) disposer failures.
